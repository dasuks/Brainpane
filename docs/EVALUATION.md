# 실제 스킬 의미 판단 평가

`fixtures/demo.json`은 예정된 패치입니다. `fixtures/conversation.json`은 같은 8개 공개 발언만 담으며 기대 패치를 포함하지 않습니다. 데모·단위 테스트는 상태 처리/재생의 정확성을 확인할 뿐 LLM의 이해를 증명하지 않습니다.

## 수동 8턴 평가

1. `brainpane run --session eval-<unique-id> -- codex` 또는 `-- claude`를 실행합니다. 모델 판단 평가이므로 기존 CLI 사용량을 소비합니다.
2. 준비 후 `fixtures/conversation.json`의 발언을 순서대로 대화 입력란에 제공합니다. 각 사용자 발언은 한 턴씩 넣고 답변/지도 발행을 기다립니다. 5번 어시스턴트 발언은 평가에 주어진 공개 대화 자료임을 명시하고 그대로 제공할 수 있습니다. 실제 모델이 그 문장을 말했다고 가장하지 마세요.
3. 평가 대상 에이전트에게 `fixtures/demo.json`이나 기대 패치를 읽게 하지 마세요. 주제 ID/이름을 정답과 같게 만들 필요도 없습니다.
4. 각 턴 이후 오른쪽 지도와 `context`를 확인하고 아래 관찰을 기록합니다. 갱신이 없으면 누락 자체를 먼저 기록하고, sync를 한 번 수행한 결과를 따로 기록합니다.

| 턴 | 관찰할 것 |
| --- | --- |
| 1 | 원래 질문을 출발점으로 보존한다. 시작 지침을 주제로 삼지 않는다. |
| 2 | 지도라는 해결 방식의 의미 있는 가지가 생긴다. |
| 3 | 호환성 하위 주제가 생긴다. cmux의 지원 능력을 지어내지 않는다. |
| 4 | 가시성으로 이동하되 호환성은 삭제/해결하지 않는다. |
| 5 | 웹 패널 발언은 제안이며 결정이 아니다. |
| 6 | 비용 주제가 이미 있으면 재사용하고 없으면 적절히 추가한다. |
| 7 | 비용을 보류하고 기존 가시성 ID로 돌아간다. |
| 8 | 비교 중인 상태를 유지하며 잘못된 확정 기록을 남기지 않는다. |

추가로 짧은 맞장구, 기존 주제를 단순 언급하는 발언, 같은 주제를 다시 설명하는 발언을 넣어 불필요한 노드/이동이 생기지 않는지 봅니다. 사용자가 제목/상태를 고친 후 AI 업데이트가 보호 값을 유지하는지도 확인합니다.

## 실제 CLI 자동 검사

`npm run test:codex`와 `npm run test:claude`는 실제 설치된 CLI를 Brainpane 안에서 실행하고 네 개의 짧은 합성 대화를 입력합니다. 고정 패치나 별도 LLM API를 사용하지 않습니다. 처음 질문 → 가시성 → 비용 → 기존 가시성으로 돌아가는 ID 재사용과 보류를 검사합니다. 전체 8턴 의미 평가와는 별개의 작은 smoke test입니다.

프로젝트 신뢰/도구 권한 화면에서 멈추면 이를 실패/미검증으로 기록합니다. 테스트 도구의 `--trust-project`는 명시적으로 전달했을 때 현재 테스트 프로젝트의 신뢰 확인 한 번만 처리합니다. 일반 제품 실행에서는 이를 자동 처리하지 않습니다. 실제 검증 중 이미 알고 있는 이 저장소에서만 사용했습니다.

결과는 ignored `.brainpane/test-results/`에 저장됩니다. 원문·토큰·실제 계정 화면을 공개 저장소에 올리지 마세요. 공개 검증 보고에는 CLI/OS 버전, 통과한 관찰, 제약만 기록합니다.
